# 帆船赛现场控制和申诉处理

源提示词摘要：竞赛官维护组别、航线、起航时间和处罚记录，计时员提交到达数据，裁判处理抗议、重赛、弃权和成绩更正；冲突或重复处罚进入复核，操作保留时间线。

## 技术栈

React 19、TypeScript、Vite、Ant Design、Redux Toolkit、RTK Query、React Router、React Hook Form、Zod、i18next。

## 本地运行

```bash
npm install
npm run dev
```

开发端口：`62024`

## 可用流程

- 竞赛控制：起航倒计时、比赛状态切换、船队和航线查看。
- 成绩管理：录入净用时和处罚秒数，标记成绩更正并发布正式成绩。
- 抗议处理：提交抗议、进入复核、支持抗议或维持原成绩，同时更新事件时间线。
- 数据使用 localStorage 持久化，刷新页面后继续保留。

## 并发与一致性规则

多标签页（计时员 / 仲裁 / 竞赛官）同时操作同一场比赛时：

- **乐观锁版本校验**：每条成绩与每条抗议都带单调递增的 `version`。保存净用时/处罚/说明或给出抗议结论时必须带“打开时的基线版本”；若另一标签页已先保存，后到保存被拦截，不会覆盖对方结果。
- **冲突保留原文**：拦截后在“冲突”面板展示三方数据（你的原文 / 对方现值 / 你的输入），输入原样保留；可放弃，或经二次确认后以当前版本为基线强制覆盖（生成新版本并写入时间线）。
- **跨标签页合并**：监听 `storage` 事件，按条目版本与事件 id 做并集合并，配合顶层 `rev`，避免晚到保存整包覆盖。
- **名次失效重算**：净用时、处罚秒数变化，或抗议给出终局结论（接受/驳回）后，所有 `official` 成绩自动转为 `invalidated`，正式名次标记失效，需重算后重新发布；仅改文字说明不影响名次。
- **整批发布原子化**：批量发布在单 reducer 内完成，可模拟“发布到第 N 项中途失败”。失败时整批回滚并恢复上一版正式成绩快照，失败项及后续项进入“待重试队列”（含原因、批次号、尝试次数），并在事件时间线记录失败、回滚与待重试条目；重试成功才固化新版快照。
